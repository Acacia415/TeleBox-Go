# Telegram 输出规范

Go 重构版以备份中的原插件为视觉参考，但不机械复制冗长提示。

## 基本结构

- 标题使用一个语义明确的 Emoji，例如 `📊 运行状态`。
- 标题、分区、正文之间留一个空行。
- 字段统一使用 `• 名称：值`，同一层级不混用多种符号。
- 成功、失败、警告、处理中分别使用 `✅`、`❌`、`⚠️`、`⏳`。
- 命令、ID、地址、金额和版本号使用等宽样式；标题和分区可使用粗体。
- 优先编辑用户发出的命令，避免额外产生状态消息。

## 文案

- 先给结果，再给必要补充。
- 处理中提示保持在一行，例如 `⏳ 查询中…`。
- 不向用户暴露堆栈、上游响应体、文件路径或原始内部错误。
- 日常错误只说明原因和下一步，例如 `❌ 未找到该用户`。
- 删除“如果问题持续请联系管理员”“建议稍后重试”“未知错误”等套话。
- 不使用拟人化道歉、营销语气或过量 Emoji。

## 兼容

- gotd 传输使用 Telegram HTML 实体实现粗体和等宽文本。
- 不支持富文本的测试替身或未来传输会自动降级为等价纯文本。
- 所有动态内容必须先做 HTML 转义。
